# CLI Agent – הוראה בעברית → פקודת Windows CMD

פרויקט Prompt Engineering: Agent שמקבל הוראה בשפה טבעית ומחזיר פקודת CLI ל-Windows CMD, באמצעות מודל `openai/gpt-oss-120b` דרך Groq (`temperature=0`).
**האפליקציה מחזירה פקודות בלבד ואינה מריצה אותן.**

## הרצה

1. יוצרים קובץ `.env` עם השורה: `GROQ_API_KEY=המפתח_שלך` (הקובץ לא מועלה לגיטהאב)
2. `uv sync`
3. `uv run app.py`

להחלפת איטרציה משנים בשורה `PROMPT = open("prompt_v1.txt", ...)` את שם הקובץ, ומריצים מחדש את האפליקציה.

## גרסאות הפרומפטים

| קובץ | איטרציה | שינוי |
|---|---|---|
| `prompt_v1.txt` | 1 | פרומפט בסיס |
| `prompt_v2.txt` | 2 | הגבלה ל-Windows CMD, והחזרת הפקודה בלבד ללא Markdown |
| `prompt_v3.txt` | 3 | כלל אבטחה: אין להחזיר פקודות מסוכנות (del, shutdown, format) ויש לסרב |
| `prompt_v3_extended.txt` | מקרי קצה | גרסה מורחבת עם קודי פלט קבועים (BLOCKED / CONFIRM:), שהורצה על 6 מקרי קצה בלבד |

## תוצאות (15 תרחישי בדיקה זהים בכל איטרציה)

| איטרציה | תקין | חלקי | שגוי | בקשת הכיבוי |
|---|---|---|---|---|
| 1 | 2 | 1 | 12 | הוחזרה `sudo shutdown -h +1` (מסוכן) |
| 2 | 11 | 0 | 3 | הוחזרה `shutdown /s /t 60` (לא בטוח) |
| 3 | 13 | 0 | 1 | המודל סירב להחזיר פקודה |

## הכשלים המעניינים ולקחים

- **איטרציה 1:** המודל החזיר כמעט רק פקודות Linux (`ls`, `touch`, `mv`, `ps`). בלי הגדרת מערכת הפעלה הוא מניח Linux.
- **איטרציה 2:** הגדרת מערכת ההפעלה פתרה את בעיית ה-Linux, אך נשארו טעויות בנתיבים (`new\.txt`, `\*.txt`, לוכסנים מיותרים) ופקודת כיבוי עדיין הוחזרה.
- **איטרציה 3:** כלל האבטחה חסם את בקשת הכיבוי, אך נשארה טעות בשינוי שם קובץ (`ren old.txt -new.txt` במקום `new.txt`). פקודה תקינה תחבירית אינה בהכרח נכונה.
- **מקרי קצה (על הפרומפט המורחב):** בקשות מסוכנות ואסורות נחסמו (BLOCKED). בבקשה עם כמה שלבים המודל העתיק את כל הקבצים במקום רק קובצי txt. בבקשות שאינן פקודה (שיר, מזג אוויר) ההתנהגות לא עקבית, כי הפרומפט לא מגדיר מה לעשות במקרה כזה.

## מגבלות

- הפקודות נבדקו ידנית מול Windows CMD ולא הורצו בפועל (לא בוצע sandbox).
- מקרי הקצה הורצו רק על הגרסה המורחבת, ולא על שלוש האיטרציות.
